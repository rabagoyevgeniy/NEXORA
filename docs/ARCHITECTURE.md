# NEXORA — Архитектура (Фаза 2, D-071–D-072)

> Скелет систем для Cursor. Числа и лимиты → Q-08.

## Принципы

1. **Сервер-авторитарность**: клиент никогда не вычисляет исходы — только рендерит присланный сценарий резолва. Движок существует в одной реализации (edge).
2. **Одновременность на уровне RLS**: закоммиченный ход противника физически недоступен из БД до коммита обоих. Секретность — политика строк, не флажок UI. (Урок CoachFlow: RLS-дыры = P0.)
3. **LLM только на входе** (парсинг), никогда в резолве (D-065).

## Бэкенд: Supabase + Edge Functions

**Таблицы ядра**: mages, duels, turns, clusters (эмбеддинг, каноническая структура, хэш — D-063), erosion_counters (кластер × арена — D-043), chronicle, signatures, ink_ledger, notebook, admirations.

**Путь хода — три функции**:
- `parse`: ступень-1 микроклассификатор (мусор/safety) → кэш кластеров → промах: LLM-парс → канонизация → хэш → черновик (RLS: виден только автору).
- `commit`: валидация хэша, фиксация цены (D-046), статус ready.
- `resolve`: триггер при ready обоих → чистая детерминированная функция (структуры + состояние + арена → новое состояние + КОМПАКТНЫЙ ЛОГ слоёв, D-085) → эрозия++, роялти (только из matchmade, с затуханием D-044/D-081, дневной кап), летопись при условиях открытия (D-014/D-024). Идемпотентна: unique(duel_id, turn_no).

**Уведомления**: Supabase Realtime (в сессии) + Web Push (асинхрон, агрегация, тихие часы).

## Фронтенд: React + Vite (Vercel)

**Метафора: дуэль = переписка.** Главный экран — инбокс живых дуэлей (как чаты). Внутри дуэли — лента: каждый резолв = «сообщение мира» (обе фразы + мини-реплей + лог слоёв), внизу поле ввода + прекаст-панель. Асинхрон получает родной паттерн мессенджера: играешь, как отвечаешь на сообщения.

**Экраны MVP**: Инициация (сцена), Инбокс дуэлей, Дуэль-переписка, Гримуар, Страница мага, Лаборатория.

**Визуальный язык боя (D-086)**: панельная раскадровка «как комикс» из трёх кадров на ход — (1) фразы как реплики магов, (2) векторная сцена столкновения (силуэты + задник из тегов арены + частицы аспектов), (3) исход + строка лога. Тот же детерминированный рендерер, скомпонованный грамматикой комикса. Генеративные иллюстрации отклонены в MVP (цена/латентность/недетерминизм/модерация).

**Тиры визуала (D-087)**: движок ЕДИН для всех (бренд, воронка, равенство в дуэли); подписка/косметика открывают СТИЛИ внутри движка (палитры, сигилы, частицы, рамки, ореолы). Пер-ход генеративное видео отклонено навсегда (арифметика: доллары себестоимости на дуэль при $6/мес).

**«Кинематограф» (D-087, после запуска)**: премиум-артефакт по запросу — избранный реплей → лог → структурное описание сцены → Seedance-промпт → Higgsfield-рендер → «твой фильм готов». Лимит в топ-тире (~2/мес) или разовая покупка; в пайплайн идут только реплеи, прошедшие ворота публикации (D-080); шеринг с водяным знаком = маркетинг, купленный и распространённый самим игроком. Партнёрство Higgsfield — после трекшна; до того — API-клиент (референс-персонажи решают консистентность магов).

**Реплей (D-085)**: кадры НЕ хранятся — хранится компактный лог резолва; клиент/реплей-страница рендерит детерминированно версионированным рендерером (version в логе). Частицы = функция аспектов из библиотеки примитивов (D-079). Реплей-страница публична + поле «Скажи своё слово» (воронка D-034).

**Стейт**: TanStack Query + Realtime-подписки (паттерны CoachFlow переиспользуются).

## Безопасность

- RLS: черновики — только автор; закоммиченное — скрыто до двойного коммита; летопись — публичное чтение.
- **Состояние дуэли читается ТОЛЬКО через RPC/edge с применением инфо-эффектов наблюдателя (D-077)**: прямой select полей противника (мана, эффекты) запрещён RLS — иначе маска разума снимается через DevTools. Правда живёт в БД, наблюдение — в функции.
- Идемпотентность резолва: unique constraint (duel_id, turn_no) — гонка двойного коммита порождает ровно один резолв.
- Грамматика-песочница (D-061) + zod-валидация на edge.
- Rate-limits: Инициация по IP+fingerprint (осторожно с NAT операторов), парс на игрока/ход.
- Гостевые аккаунты: анонимная сессия Supabase → апгрейд при имени.
